# Purpose

This file records the rough expression-library model developed in this chat.

The expression library translates facets into observable behavioral evidence that can be used by individuals, therapists, facilitators, or third-party observers.

---

# Core Principle

Expressions are not traits.

Expressions are observable, repeatable behaviors that provide evidence for a facet.

The expression layer should answer:

```text
What observable behavior supports this facet?
```

---

# Observer-Readable Behavior Format

The preferred expression wording is observer-readable behavior.

This was chosen instead of first-person self-report wording.

## Avoid

```text
I speak up when my position is challenged.
```

## Use

```text
Speaks up when their position is challenged.
```

Reason:

Observer-readable phrasing works across multiple use cases:

- Self-mapping
- Therapist mapping a client
- Third-party observation
- Facilitated comparison of self-report and observer-report

This maintains a consistent perspective format even when the evaluator changes.

---

# Expression Categories

All six expression constituent categories are retained during the rough drafting stage:

| Category | Function |
|---|---|
| Behavioral | Observable action or conduct. |
| Communication | Spoken, written, or expressive behavior. |
| Decision-Making | Choice pattern or priority selection. |
| Relational | Interpersonal behavior or social positioning. |
| Problem-Solving | Response to obstacle, conflict, uncertainty, or complexity. |
| Self-Management | Internal regulation, recovery, inhibition, or sustained control. |

---

# Reason for Keeping All Six Categories

The decision in this chat was to keep all expression categories because each one provides a different context window.

A facet may express differently depending on social, behavioral, emotional, relational, or problem-solving context.

Example: Reliability

| Category | Expression Direction |
|---|---|
| Behavioral | Completes agreed tasks. |
| Communication | Gives updates when delayed. |
| Decision-Making | Chooses follow-through over convenience. |
| Relational | Becomes dependable to others. |
| Problem-Solving | Creates systems to prevent dropped obligations. |
| Self-Management | Continues despite fluctuating motivation. |

This wide expression spread supports identity mapping across life settings.

# Rough Scenario Option Structure

The working rough model discussed in this chat:

```text
Scenario Card
↓
8 response options
↓
6 additive expression options
2 inverse-pole expression options
↓
10 tokens allocated
↓
Maximum 5 tokens per option
```

This is provisional and should be finalized in the Token Economy Model.

# Positive Expression Options

Positive expression options represent functional observer-readable behaviors that support a target facet.

Example:

```text
Explains their position clearly when others disagree.
```

Positive options may contribute to:

- Facet activation
- Expression category scoring
- Constructive expression evidence

---

# Inverse-Pole Expression Options

Inverse-pole options should not represent mere absence of a trait.

They should represent distorted, aversive, coercive, avoidant, manipulative, or malformed expression patterns.

## Weak inverse item

```text
Does not speak up.
```

This may indicate low assertiveness, inhibition, fear, context restriction, role suppression, or uncertainty.

## Stronger inverse-pole item

```text
Overrides others rather than stating a position clearly.
```

or:

```text
Uses pressure to force agreement instead of communicating a position directly.
```

---

# Key Distinction

The chat established this distinction:

```text
Low expression
≠
Aversive expression
```

A participant can show low evidence of a facet without showing harmful or distorted expression.

Inverse options should represent active counter-patterns or corrupted implementation, not simple absence.

---

# Karma Shadow Linkage

Karma should inform the flavor of inverse-pole options.

Karma does not replace personality scoring.

Instead, it identifies when a personality expression is used in an aversive, ethically distorted, coercive, exploitative, deceptive, or avoidant direction.

Example:

## Facet

```text
Influence
```

## Expression Category

```text
Communication
```

## Additive expression

```text
Explains an idea in a way that helps others understand the choice.
```

## Inverse-pole expression

```text
Frames information selectively to steer others without giving them the full picture.
```

## Possible Karma shadow

```text
Strategic Deception
Exploitative Orientation
```

# Surface Frame and Latent Mechanism

The chat refined inverse expression design into two layers:

## Surface Frame

What the option appears to offer.

Examples:

- Leadership
- Care
- Fairness
- Confidence
- Efficiency
- Independence
- Honesty
- Protection
- Competence

## Latent Mechanism

What the behavior actually expresses.

Examples:

- Control
- Manipulation
- Avoidance
- Dominance
- Image protection
- Blame deflection
- Coercive helping
- Boundary violation
- Threat sensitivity
- Self-serving distortion

Working rule:

```text
The surface frame attracts the desired self.
The latent mechanism scores the actual expression.
```

---

# Temptation Design Rather Than Deception Design

The chat rejected the idea of punishing people for choosing too many favorable-looking options.

Instead, inverse options should be written as psychologically plausible, identity-attractive distortions.

The goal is not to trick the evaluator.

The goal is to reveal whether the evaluator understands the behavioral pathway to the desired identity.

Working principle:

```text
Do not score “too good.”
Score “good costume, bad mechanism.”
```

# Examples of Identity-Attractive Aversive Options

## Leadership shadow

Functional expression:

```text
Clarifies the goal, asks what each person can realistically handle, and organizes the next steps.
```

Aversive leadership-coded option:

```text
Takes control of the plan quickly so the group stops wasting time debating.
```

Surface frame:

```text
Decisive leadership / efficiency / confidence
```

Latent mechanism:

```text
Dominance / low deliberation / low cooperation / possible control orientation
```

---

## Compassion shadow

Functional expression:

```text
Asks what support would be useful before deciding how to help.
```

Aversive care-coded option:

```text
Gives immediate help that feels compassionate without checking whether it may worsen the situation.
```

Surface frame:

```text
Kindness / generosity / responsiveness
```

Latent mechanism:

```text
Low prudence / low moral sensitivity / possible performative helping / self-soothing care
```

---

## Efficiency shadow

```text
Skips discussion so the group can move faster.
```

Surface frame:

```text
Efficiency
```

Latent mechanism:

```text
Low cooperation / dominance / low deliberation
```

---

## Care shadow

```text
Steps in to solve the person's problem before asking what they want.
```

Surface frame:

```text
Helpfulness
```

Latent mechanism:

```text
Paternalism / autonomy violation
```

# Expression Option Syntax

Recommended option-writing formula:

```text
[Observer-readable behavior] + [contextual pressure] + [surface-valid motive]
```

Simplified syntax:

```text
Does X in order to Y when Z.
```

Functional example:

```text
Clarifies the group's goal so everyone can coordinate under time pressure.
```

Aversive example:

```text
Takes over the plan so the group stops slowing things down.
```

# Provisional Expression Record Schema

Each draft expression item should eventually include:

| Field | Purpose |
|---|---|
| Option ID | Unique option identifier. |
| Scenario ID | Parent scenario. |
| Observer-readable option text | Final card-facing behavior text. |
| Surface frame | The attractive identity/value frame. |
| Latent expression | The scored behavioral mechanism. |
| Aspect | Parent aspect. |
| Facet | Parent facet. |
| Expression category | Behavioral, Communication, Decision-Making, Relational, Problem-Solving, or Self-Management. |
| Polarity | Functional, aversive, or contextual. |
| Karma shadow | Possible Karma dimension or negative-pole linkage. |
| Constraint tag | Scenario condition that affects interpretation. |
| Contradiction pair | Option that creates meaningful conflict if both receive tokens. |
| Token value | Allocated score from evaluator. |
| Scoring effect | Activation, integrity, shadow, or reconciliation impact. |

# Important Warning

Aversive expression should not always subtract from raw facet strength.

Example:

```text
Dominates the group to force action.
```

This may indicate:

- High Agency
- High Leadership activation
- Low or mixed expression integrity
- Possible Karma shadow
- Possible reconciliation need

Thus, inverse options should often affect:

```text
Expression Integrity
Karma Shadow Flagging
Reconciliation Pressure
```

rather than simply reducing trait activation.

# Three-Layer Expression Scoring Concept

The chat proposed separating expression interpretation into three outputs:

## 1. Trait Activation Score

Question:

```text
Is the facet behaviorally activated?
```

## 2. Expression Integrity Score

Question:

```text
Is the facet being expressed coherently, constructively, and context-sensitively?
```

## 3. Karma Shadow Flag

Question:

```text
Is the tendency being expressed in a harmful, exploitative, deceptive, coercive, avoidant, or distorted way?
```

---

# Reconciliation Relevance

Malformed expression should trigger reconciliation rather than condemnation.

Possible reconciliation interpretations discussed:

- Role Misinterpretation
- Desired-Self Projection
- Low Expression Literacy
- Context Misread
- Karma-Expression Mismatch
- Trait Activation with Distorted Implementation
