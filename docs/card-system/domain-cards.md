# Domain Cards

## 1. Definition

A Domain is the highest-level organizational category within the Tessera personality architecture.

Domains summarize groups of related aspects and function as anchor nodes for identity map construction.

Domains are not primary assessment units.

---

## 2. Purpose

### Organizational Purpose
Groups related aspects into a coherent structure.

### Summary Purpose
Provides a high-level overview of personality organization.

### Mapping Purpose
Creates visual hierarchy and navigation within the identity map.

### Educational Purpose
Introduces personality structure in an accessible format.

---

## 3. Current Domain Set

- Extraversion
- Agreeableness
- Conscientiousness
- Neuroticism
- Openness / Intellect
- Honesty-Humility

These domains are manually maintained and revised only when supported by appropriate academic evidence.

---

## 4. Domain Design Requirements

A domain must:

- Contain multiple aspects
- Represent broad personality territory
- Remain relatively stable across contexts
- Possess empirical support
- Provide meaningful organizational value

---

## 5. Domain Card Specification

Card Type: Domain

Function: Organizational Anchor

Placement: Top Layer of Identity Map

Current Quantity: 6

Suggested Contents:

- Domain Name
- Brief Definition
- Associated Aspects
- Identity Map Connections

---

## 6. Current Assessment Status

Domains are not directly assessed.

The current assessment architecture begins at the Aspect level.

Any future domain aggregation methodology will be developed only after the aspect model has been finalized.

## 8. Identity Map Function

Domains occupy the highest organizational layer of the personality map.

Domains serve as parent nodes for all subordinate aspect structures.

---

## 9. Educational Utility

Domains provide a simplified entry point into personality structure.

They allow players to understand how individual aspects belong to larger personality systems.

---

## 10. Manual Revision Policy

Domain additions, removals, or revisions require manual review and supporting academic resources.

The Tessera system does not automatically update domain architecture based on emerging literature.
